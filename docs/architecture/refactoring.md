# 구조 분석·리팩토링 판단

| 확인한 문제 | 적용한 변경 | 선택 이유 |
|---|---|---|
| 홈 한 파일에 소개·사진·사례·근거·이력 혼재 | 섹션 4개와 사진·서비스 그림 분리 | 한 섹션 수정이 다른 섹션의 마크업을 건드리지 않음 |
| 단일 스크립트가 탐색·사진·미리보기·인쇄 처리 | 수명 조합과 기능별 초기화 분리 | 이벤트 정리 계약은 하나로 유지 |
| 목차·카드·기본 미리보기 ID·외부 링크가 코드에 중복 | portfolio.json에 편집용 라벨·미리보기·리소스 정의 | 데이터 수정이 각 표현에 반영됨 |
| site.json의 이름·headline 중복과 미사용 설정 | 이름은 portfolio에서 읽고 미사용 필드 제거 | 두 JSON의 값이 엇갈리는 경로 제거 |
| 인쇄가 미리보기 DOM 구조에 직접 의존 | 작은 PreviewSelection 인터페이스 전달 | 인쇄는 선택·초기화·조회만 알면 됨 |
| 사례마다 종류 조건문으로 렌더링 분기 | 종류→Astro 컴포넌트 레지스트리 | 공통 사례 구조와 그림 변경 분리 |
| 스타일 2,340줄·1,240줄에 화면·인쇄·상호작용 누적 | 의미 있는 구간별 CSS 모듈·진입점 분리 | 기존 cascade 순서를 보존하면서 탐색 범위 축소 |
| 이전 시안의 미사용 스타일 159개 선택자 | 소스 사용처와 동적 클래스 확인 후 제거 | 화면·인쇄에서 쓰는 규칙은 보존 |
| 같은 조건·선택자·값의 CSS 선언 반복 | 앞선 동일 선언 제거 | 최종 규칙과 우선순위 보존 |

**SOLID:** SRP가 실제 문제였다. 화면·수명·편집 데이터의 변경 이유를 분리했다. OCP는 종류별 시각화 교체 지점에만 적용했다. ISP·DIP는 인쇄가 사용하는 작은 선택 인터페이스로 반영했다. 상속 계층이 없어 LSP 위반을 별도로 찾지는 않았다.

**패턴:** 시각화 레지스트리는 Strategy의 단순한 형태다. 클래스 계층 대신 Astro 컴포넌트 매핑을 사용한다. 브라우저 이벤트는 플랫폼의 Observer 방식을 따르고, AbortSignal로 구독 수명을 묶는다. 저장소·팩토리·DI 컨테이너는 현재 정적 사이트의 문제 해결에 필요하지 않아 추가하지 않았다.

독립적인 제목·짧은 역할·검색 설명은 읽는 위치에 맞춘 편집 필드다. 같은 문구를 코드에 다시 적지 않는다. 설명용 엔진 그림의 숫자는 실험 성능 수치와 다른 의미이므로 하나로 합치지 않는다.

검사: 스키마의 잘못된 ID·기본 선택·근거 인덱스·HTTPS 주소를 거부하는 테스트, 실제 프로젝트 ID에 의존하지 않는 동작 테스트, 정적 HTML 콘텐츠·앵커·리소스 포함 검사. CSS 분리는 변경 전후 화면의 계산 스타일과 인쇄용 규칙을 비교했다. 전체 빌드 CSS에서 유지된 선언 2,312개의 값은 일치했다. 삭제된 선언 422개는 미사용 선택자·애니메이션에 속했다.

검수 결과: `pnpm verify` 통과. 브라우저의 초기 요소 784개에서 계산 스타일·텍스트가 일치했고, 390px에서 누락 이미지·가로 넘침 없이 키보드 펼침·목차 포커스·현재 장 표시를 확인했다. 사진 열기·닫기 후 포커스 복귀도 확인했다. 공통 스타일은 1,240줄에서 641줄로 줄였다. 네이티브 인쇄 대화상자·실물 출력·원격 배포는 이번 구조 변경 검수에 포함하지 않았다.
