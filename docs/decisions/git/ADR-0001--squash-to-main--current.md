# ADR-0001 · dev 스쿼시 → main, main 역머지

관심사: git. 적용: FLOW-001.

## 맥락

혼자 관리하는 공개 포트폴리오다. 작업 중에는 관심사별로 잘게 커밋하고, 공개 이력은 반영 단위로 읽히길 원한다. 기능 브랜치와 워크트리가 쌓여 개인정보가 든 옛 커밋이 로컬에 남은 적이 있다.

## 대안

- main 하나에 직접 커밋: 작업 커밋이 그대로 공개 이력이 된다.
- dev → main 일반 머지: 공개 이력에 작업 커밋이 모두 섞인다.
- dev → main 스쿼시만: 다음 반영에서 이미 들어간 변경이 다시 충돌한다.
- **dev → main 스쿼시 + main → dev 역머지**

## 선택과 이유

마지막 안. main은 반영 하나가 커밋 하나라 되돌리기·추적이 쉽고, dev는 세부 이력을 보존한다. 역머지로 dev가 항상 main을 포함해 다음 스쿼시가 깨끗하다. 브랜치를 둘로 제한해 지울 것을 놓칠 자리를 없앤다.

## 결과

- 배포는 main에서만 일어난다. dev 푸시는 검증만 한다.
- dev 이력에는 반영마다 역머지 커밋이 하나씩 생긴다.
- 협업자가 생겨 기능 브랜치·PR 리뷰가 필요해지면 이 결정을 재검토한다.
